# OMP Remote v0.1.0

OMP Remote is a phone-first PWA for supervising Oh My Pi coding sessions from a private Tailnet. It is an independent community project and is not affiliated with or endorsed by Oh My Pi.

This is a pre-1.0, best-effort release. Minor releases may change compatibility.

## Capabilities

- View ordinary terminal OMP sessions that register through the installed user extension.
- Launch and supervise multiple OMP RPC sessions from a responsive desktop or mobile dashboard.
- Reconnect to transcripts; prompt, steer, and abort sessions; change supported model and effort settings; and answer supported OMP `ask` requests.
- Inspect supported tool disclosures, application errors, saved working directories, and Git branch state, and switch branches when the session state permits it.
- Install the dashboard as a PWA and opt each device into independent best-effort input-required and session-idle notifications.
- Run a loopback-only daemon as a macOS launchd or Linux systemd user service and expose it privately with Tailscale Serve.

## Supported platforms

- Host: macOS or Linux.
- Runtime: Node.js `>=24.18.0` and pnpm `11.17.0`.
- OMP: `18.0.0`.
- Client: current Safari or Chrome PWA. iOS/iPadOS Web Push requires installation to the Home Screen.
- Remote network: Tailscale on the host and client device.

## Security and privacy model

The daemon and extension listener bind only to loopback, and Tailscale Serve supplies private HTTPS access. OMP Remote has no application login or authorization layer. Tailnet membership and ACLs are the authentication and authorization boundary: treat every user and device allowed to reach the host as able to view transcripts and use session controls. Do not expose daemon port `4387` directly to a LAN or the public internet.

Transcripts, application errors, and service logs can contain prompts, tool output, paths, process details, and secrets. Notification previews can reveal a session name and status on a receiving device's lock screen. Review Tailnet membership and ACLs, device preview settings, and any material before sharing it.

Push endpoints, browser encryption keys, preferences, and the VAPID signing key are stored locally in `~/.omp/remote/push-subscriptions.json`; there is no OMP Remote notification relay or account service. Push payload content is encrypted for the browser push service, while that service still handles delivery metadata.

See [SECURITY.md](https://github.com/howarewoo/omp-remote/blob/main/SECURITY.md) for the supported-version and vulnerability-reporting policy.

## Install

Install OMP 18.0.0, Node.js 24.18.0 or newer, pnpm 11.17.0, Git, and Tailscale first. Sign the host and phone into the same Tailnet and restrict access with Tailnet ACLs. Then run the exact public installation command:

```bash
git clone --branch v0.1.0 https://github.com/howarewoo/omp-remote.git && pnpm --dir omp-remote run setup
```

Setup verifies the required Node, pnpm, and OMP versions plus Tailscale; installs the frozen dependency graph; builds the workspace; installs the OMP user extension and host user service; waits for the service to identify itself as healthy; and then configures Tailscale Serve. It stops at the first failed stage. If Tailscale prints an approval URL, enable Serve there and rerun the same idempotent command.

Every workspace package is private. This release is distributed as source from GitHub; no npm package is published or required by the installation command.

## Upgrade

Upgrade in place and rerun setup:

```bash
cd omp-remote
git pull --ff-only
pnpm run setup
```

Setup replaces the build, extension, and service definition while preserving `~/.omp/remote`. On macOS it unloads and reloads the launch agent. On Linux it reloads the systemd user definition, enables the service, and restarts it. Setup waits for the restarted daemon to become healthy before changing Tailscale Serve.

Start new terminal OMP sessions so they load the new extension. Preserve `~/.omp/remote/push-subscriptions.json` to retain the VAPID key and device registrations. If that file is reset or restored without matching browser state, disable and re-enable the desired alerts once on every affected device.

## Uninstall

Follow the ordered [manual uninstall guide](https://github.com/howarewoo/omp-remote#manual-uninstall):

1. Stop and remove the macOS launchd or Linux systemd user service.
2. Inspect `tailscale serve status` before changing Serve. Run `tailscale serve reset` only when the OMP Remote proxy is the node's sole mapping; otherwise preserve unrelated mappings and remove only the OMP Remote mapping. Verify the proxy is gone.
3. Remove the installed OMP extension and restart terminal OMP sessions.
4. Only by explicit choice, delete `~/.omp/remote` and macOS service logs.
5. Only by explicit choice, delete the clone.

The guide includes exact platform commands and non-destructive checks. No uninstall script runs these destructive choices automatically.

## Known limitations

- The project targets one trusted user and has no application-level authentication. Tailnet membership and ACLs must provide the access boundary.
- Hosts and supported clients are limited to the matrix above; compatibility outside it is not claimed.
- OMP Remote can invoke only commands exposed by OMP's RPC or extension APIs. Terminal-only slash commands, including `/btw`, must be run in the local terminal.
- Web Push is best effort. The host must be awake, online, and running the daemon, and a delayed or missing notification does not change authoritative session state.
- Each browser or installed PWA must opt in separately. iOS/iPadOS cannot subscribe from an ordinary Safari tab.
- Replacing or losing the local VAPID key invalidates existing notification subscriptions until each device opts in again.
